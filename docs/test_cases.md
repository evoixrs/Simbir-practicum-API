# Тест-кейсы для API-сервиса сущностей

## TC-01: Создание сущности, ручка /api/create.

**Предусловия:**
- Тестовый стенд запущен и доступен по адресу `http://localhost:8080`.
- Swagger-документация доступна по адресу `http://localhost:8080/api/_/docs/swagger/`.

**Тестовые данные для создания:**

```json
{
  "addition": {
    "additional_info": "Дополнительные сведения <unique_suffix>",
    "additional_number": 123
  },
  "important_numbers": [42, 87, 15],
  "title": "Заголовок сущности <unique_suffix>",
  "verified": true
}
```

| № | Шаг                                                                       | Ожидаемый результат |
|---|---------------------------------------------------------------------------|---------------------|
| 1 | Отправить `POST /api/create` с валидным телом запроса                     | API возвращает статус-код `200 OK`. `Response body` содержит строку с `id` созданной сущности. Заголовок `content-type` равен `text/plain; charset=utf-8` |
| 2 | Отправить `GET /api/get/{id}`, где `{id}` взять из `Response body` шага 1 | API возвращает статус-код `200 OK`. `Response body` содержит данные созданной сущности |
| 3 | Десериализовать `Response body` шага 2 в объект `EntityResponse`          | Ответ успешно преобразован в объект |
| 4 | Проверить данные созданной сущности                                       | Поля `title`, `verified`, `addition.additional_info`, `addition.additional_number`, `important_numbers` соответствуют данным из запроса создания. Поля `id` и `addition.id` заполнены |

**Постусловия:**
- Удалить созданную тестовую сущность через `DELETE /api/delete/{id}`.

**Ожидаемый результат:**
- Сущность успешно создана.
- API возвращает строку с `id` созданной сущности.
- Созданная сущность доступна через `GET /api/get/{id}`.
- Данные созданной сущности соответствуют отправленному запросу.

## TC-02: Удаление сущности, ручка /api/delete/{id}.

**Предусловия:**
- Тестовый стенд запущен и доступен по адресу `http://localhost:8080`.
- Создана тестовая сущность через `POST /api/create`.
- Получен `id` созданной сущности из `Response body` запроса создания.

**Тестовые данные для создания:**

```json
{
  "addition": {
    "additional_info": "Дополнительные сведения <unique_suffix>",
    "additional_number": 123
  },
  "important_numbers": [42, 87, 15],
  "title": "Заголовок сущности <unique_suffix>",
  "verified": true
}
```

| № | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Отправить `DELETE /api/delete/{id}` с идентификатором созданной сущности | API возвращает статус-код `204 No Content`. В `Response headers` присутствует заголовок `date` |

**Постусловия:**
- Дополнительная очистка не требуется: тестовая сущность удаляется в ходе выполнения тест-кейса.

**Ожидаемый результат:**
- Сущность успешно удалена.
- API возвращает `204 No Content` на запрос удаления созданной сущности.

```json
{
  "addition": {
    "additional_info": "Дополнительные сведения <unique_suffix>",
    "additional_number": 123
  },
  "important_numbers": [42, 87, 15],
  "title": "Заголовок сущности <unique_suffix>",
  "verified": true
}
```

| № | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Отправить `GET /api/get/{id}` с идентификатором созданной сущности | API возвращает статус-код `200 OK`. `Response body` содержит объект сущности с полями `id`, `title`, `verified`, `addition`, `important_numbers` |
| 2 | Десериализовать `Response body` в объект `EntityResponse` | Ответ успешно преобразован в объект |
| 3 | Проверить идентификатор сущности | Поле `id` в ответе равно идентификатору созданной сущности |

**Постусловия:**
- Удалить созданную тестовую сущность через `DELETE /api/delete/{id}`.

**Ожидаемый результат:**

- Ответ соответствует модели `EntityResponse`.
- Данные полученной сущности совпадают с данными, отправленными при создании.

## TC-04: Получение списка сущностей, ручка /api/getAll.

**Предусловия:**
- Тестовый стенд запущен и доступен по адресу `http://localhost:8080`.
- Созданы две тестовые сущности через `POST /api/create`.
- Получены `id` созданных сущностей из `Response body` запросов создания.

**Тестовые данные для создания:**

```json
[
  {
    "addition": {
      "additional_info": "Дополнительные сведения 1 <unique_suffix>",
      "additional_number": 123
    },
    "important_numbers": [42, 87, 15],
    "title": "Заголовок сущности 1 <unique_suffix>",
    "verified": true
  },
  {
    "addition": {
      "additional_info": "Дополнительные сведения 2 <unique_suffix>",
      "additional_number": 456
    },
    "important_numbers": [10, 20, 30],
    "title": "Заголовок сущности 2 <unique_suffix>",
    "verified": true
  }
]
```

| № | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Отправить `GET /api/getAll?verified=true&page=1&perPage=10` | API возвращает статус-код `200 OK`. `Response body` содержит список сущностей в поле `entity`, а также поля `page` и `perPage`. Заголовок `content-type` равен `application/json` |
| 2 | Десериализовать `Response body` в объект `EntityFilterResponse` | Ответ успешно преобразован в объект |
| 3 | Проверить параметры пагинации в ответе | Поля `page` и `perPage` соответствуют query-параметрам запроса |
| 4 | Найти созданные сущности в списке `entity` по `id` | Обе созданные сущности присутствуют в общем списке |
| 5 | Проверить, что найденные сущности соответствуют фильтру | Поле `verified` у найденных сущностей равно `true` |
| 6 | Проверить данные найденных сущностей | Поля найденных сущностей соответствуют данным, отправленным при создании |

**Постусловия:**
- Удалить созданные тестовые сущности через `DELETE /api/delete/{id}`.

**Ожидаемый результат:**
- API возвращает список сущностей.
- Созданные сущности присутствуют в списке с учетом переданных query-параметров.
- В ответе возвращаются параметры пагинации `page` и `perPage`.
- Данные сущностей в списке совпадают с данными, отправленными при создании.

## TC-05: Обновление сущности, ручка /api/patch/{id}.

**Предусловия:**
- Тестовый стенд запущен и доступен по адресу `http://localhost:8080`.
- Создана тестовая сущность через `POST /api/create`.
- Получен `id` созданной сущности из `Response body` запроса создания.

**Тестовые данные для создания:**

```json
{
  "addition": {
    "additional_info": "Дополнительные сведения <unique_suffix>",
    "additional_number": 123
  },
  "important_numbers": [42, 87, 15],
  "title": "Заголовок сущности <unique_suffix>",
  "verified": true
}
```

**Тестовые данные для обновления:**

```json
{
  "addition": {
    "additional_info": "Обновленные дополнительные сведения <unique_suffix>",
    "additional_number": 456
  },
  "important_numbers": [10, 20, 30],
  "title": "Обновленный заголовок сущности <unique_suffix>",
  "verified": false
}
```

| № | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Отправить `PATCH /api/patch/{id}` с валидным телом обновления | API возвращает статус-код `204 No Content`. `Response body` пустой |
| 2 | Отправить `GET /api/get/{id}` с идентификатором обновленной сущности | API возвращает статус-код `200 OK`. `Response body` содержит данные обновленной сущности |
| 3 | Десериализовать `Response body` шага 2 в объект `EntityResponse` | Ответ успешно преобразован в объект |
| 4 | Проверить обновленные данные сущности | Поля сущности соответствуют данным, отправленным в `PATCH /api/patch/{id}` |

**Постусловия:**
- Удалить обновленную тестовую сущность через `DELETE /api/delete/{id}`.

**Ожидаемый результат:**
- Сущность успешно обновлена.
- После обновления API возвращает измененные данные сущности.
- Обновленная сущность соответствует модели `EntityResponse`.
